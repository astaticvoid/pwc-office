# iOS TestFlight ship runbook

How to ship the Capacitor web build as an iOS TestFlight build — and not ship a
stale one.

## The failure this runbook exists to prevent

An Xcode archive bundles whatever `ios/App/App/public/` held at archive time.
That directory is **gitignored** and regenerated by `npx cap sync`, which
deletes it and re-copies it from `dist/`. So a build archived without a fresh
sync ships whatever the *last* sync produced — days or weeks old, behind a
clean `git status`. The first TestFlight ship did exactly this: the archive
(2026-08-29) contained the web bundle from the 2026-08-03 sync.

The guard is the last step of `make mobile-sync`:
`tools/check_mobile_sync.py` compares `dist/` against the iOS and Android
synced web dirs and exits 1 on any missing/differing/leftover file. Archive in
the same sitting as a green `mobile-sync`.

## Preflight

- `make test` and `make test-web` — the standard gates; web/render changes are
  exactly what went stale last time, so this is not optional before a ship.
- Check the App Store Connect key is present and read its IDs:

  ```sh
  ls ~/.appstoreconnect/AuthKey_*.p8       # the key itself — gitignored, perms 600
  cat ~/.appstoreconnect/README.txt        # Key ID, Issuer ID, Team ID
  ```

  The `.p8` is covered by `*.p8` in `.gitignore`. Never commit it, and never
  copy it into `dist/`, `ios/`, or anywhere the build could archive it.

## Ship sequence

1. **Bump the build number** — TestFlight rejects a build number that has
   already been uploaded. The first ship used `CFBundleVersion` 1; each
   subsequent ship must be 2, 3, …:

   ```sh
   make mobile-bump-version    # raises CURRENT_PROJECT_VERSION in the pbxproj
   ```

   It updates Debug and Release together and refuses if the two disagree.
   `CURRENT_PROJECT_VERSION` and `MARKETING_VERSION` live in the committed
   `ios/App/App.xcodeproj/project.pbxproj` — commit the bump.

2. **Sync** (the staleness guard):

   ```sh
   make mobile-sync    # rebuilds dist/ → cap sync → check_mobile_sync.py
   ```

   The last line must read `mobile web assets match dist/ for: ios, android`.
   If it exits 1 it lists exactly which files are stale; the run failed, do not
   archive.

   Do not modify `web/`, rebuild `dist/`, or re-sync between this step and the
   archive.

3. **Archive** — open the project with the guarded target, then Archive in
   Xcode:

   ```sh
   make mobile-ios     # mobile-sync (guard re-runs) + opens the project in Xcode
   # Product → Archive
   ```

   CLI equivalent:

   ```sh
   xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Release \
     -archivePath "$HOME/Desktop/App.xcarchive" -allowProvisioningUpdates archive
   ```

4. **Verify what you are about to ship** — the archive's web bundle must be
   byte-identical to `dist/`, and the version/team must be what you expect:

   ```sh
   ARCHIVE="$HOME/Desktop/App.xcarchive"
   APP="$ARCHIVE/Products/Applications/App.app"
   md5 -q "$APP/public/app.js" dist/app.js          # outputs must match
   /usr/libexec/PlistBuddy -c "Print :ApplicationProperties" "$ARCHIVE/Info.plist"
   # CFBundleVersion should be the number from step 1; Team = VYB6G7NSAS
   # (after export: unzip -p App.ipa Payload/App.app/public/app.js | md5
   #  must equal `md5 -q dist/app.js`)
   ```

5. **Upload** — Xcode Organizer → Distribute App → App Store Connect (this
   exports an `.ipa`), or CLI. For the CLI path, export the `.ipa` first
   (a `--exportOptionsPlist` with `method: app-store-connect` and
   `teamID: VYB6G7NSAS`), then upload it:

   ```sh
   xcodebuild -exportArchive -archivePath "$ARCHIVE" -exportOptionsPlist /tmp/export.plist \
     -exportPath "$HOME/Desktop/"
   xcrun altool --upload-app --file "$HOME/Desktop/App.ipa" --type ios \
     --apiKey "$ASC_API_KEY" --apiIssuer "$ASC_API_ISSUER" --verbose
   ```

   `ASC_API_KEY` / `ASC_API_ISSUER` are the Key ID / Issuer ID from
   `~/.appstoreconnect/README.txt` (optionally in `.env`, which is gitignored).

6. **Smoke-test the TestFlight build** — install it, open a few offices, and
   confirm it matches current `main` behaviour.

## If something goes wrong

| Symptom | Cause | Fix |
|---|---|---|
| `altool` refuses: `ITMS-90683 ... already exists` | build number reused | bump again and re-archive |
| Archive has old content despite a clean `git status` | archived without a fresh sync | run `make mobile-sync`, re-archive in the same sitting |
| `check_mobile_sync.py` lists diffs | `web/` changed since last sync | it is the guard working — run `make mobile-sync` |
| Xcode signs with the wrong team | personal `DEVELOPMENT_TEAM` override | committed value is `VYB6G7NSAS` (Synod); a local override must stay uncommitted |

## What an already-shipped archive contained

```sh
find ~/Library/Developer/Xcode/Archives -name "*.xcarchive" | tail -1
# hash its bundled app.js against dist/app.js — mismatch means that ship was stale
```

## Do not

- Run `npx cap open ios` bare — it bypasses the sync guard. Use the make
  targets.
- Reuse a build number.
- Commit a personal `DEVELOPMENT_TEAM`; the Synod team ID is the committed
  value (a team ID is not a secret — it ships in the binary — but the override
  is per-developer).
- Commit the `.p8` or any App Store Connect credential.
